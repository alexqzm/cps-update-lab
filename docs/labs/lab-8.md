# ЛР-8. ИИ-агент и рецепты партии: внедрение указаний, ключи, мост MCP

**Сценарии:** RN1, RA1–RA7, RM1, RM2. **Продолжительность:** 4 академических часа.

## Цель

Разобрать второй канал изменения поведения КФС — рецепты партии, которые составляет ИИ-агент.
Научиться отличать аутентификацию агента от утверждения рецепта, статическую проверку — от проверки
на модели объекта, а допуск рецепта — от защиты момента его исполнения. Увидеть, какие свидетельства
графа обнаруживают внедрение указаний, искажённые данные, похищенный ключ и подменённый мост MCP.

## Связь с реальными случаями

- [APS Control Community](https://github.com/APS-Techno/Control-Community): открытая система
  управления установками напыления; агент пишет рецепты и работает с установкой через мост MCP с
  уровнями доступа Read, Recipe и Manual. В препринте авторов
  ([arXiv:2609.12796](https://arxiv.org/pdf/2609.12796)) указано, что состязательных испытаний шлюза
  агента не проводилось. Архитектура сервера агента стенда повторяет эту схему.
- Внедрение указаний через данные, которые читает модель (indirect prompt injection), — техника
  AML.T0051.001 MITRE ATLAS и первый риск в OWASP Top 10 для приложений на больших языковых моделях.

## Теория

Рецепт меняет уставки программы контроллера, переводит насос в ручной режим и ждёт условий процесса
(`docs/agent-recipes.md`). Агент работает инструментами сервера агента: ключ определяет уровень
доступа, изменяющие команды разрешает режим управления, который переключает только оператор. Сервер
ведёт журнал с хеш-цепочкой и подписывает аттестацию авторства каждого загруженного рецепта.

Гейт рецептов решает по десяти свидетельствам q11–q52. Обязательны статическая проверка (q31), пробный
прогон на двойнике (q32) и утверждение оператора (q41). Контроллер на L2 исполняет рецепт только с
квитанцией, привязанной к дайджесту рецепта, экземпляру устройства и ревизии.

## Подготовка

```bash
./lab.sh up
./lab.sh recipes                      # 30 исходов в модельном времени
```

## Ход работы

1. **Эталон.** Выполните `./lab.sh cli recipes run RN1` и `./lab.sh cli recipe report RN1`. Запишите
   R_P^min, R_P^max и состояния q11–q52. Почему R_P^min равен порогу θ?

2. **Внедрение указаний.** Выполните `./lab.sh cli recipes run RA1`. Найдите в отчёте гейта
   (`./lab.sh cli recipe report RA1`) свидетельства со значением F и их причины. Почему L1 рецепт
   пропускает? Почему утверждение оператора не помогло?

3. **Данные и ключи.** Выполните RA2 и RA3. Сравните состояния q12, q21, q22 и q41. Что подтверждает
   аттестация авторства при похищенном ключе и чего она не подтверждает?

4. **Момент исполнения.** Выполните RA4 и RA5. Какие коды отказа выдаёт scii-agent на L2? Почему
   монитор не поднимает тревогу в RA4?

5. **Цепочка поставки инструментов агента.** Выполните RA6. По журналу сеанса
   (`runs/recipe-RA6-L0/agent/journal.jsonl` в рабочем каталоге стенда, `./lab.sh shell`) найдите
   запись пробного прогона и запись загрузки и сравните дайджесты рецепта.

6. **Скрытая функция через рецепт.** Выполните RA7. Почему на L1 рецепт отклоняет уже сервер, а на L0
   резервуар переливается?

7. **Границы.** Выполните RM1 и RM2. Предложите для каждого меру защиты и укажите, кто её применяет:
   поставщик программы контроллера, владелец политики гейта или администратор сервера агента.

8. **Живой стенд.** Выполните `./lab.sh cli live recipe-demo` и затем повторите шаги агента вручную:
   подключите Claude Code к мосту MCP или вызывайте инструменты через HTTP API сервера агента
   (`curl`, примеры — в `docs/agent-recipes.md`). Утвердите рецепт `./lab.sh approve batch-prep` и
   запустите его. Проверьте журнал: `./lab.sh journal`.

9. **Задание повышенной сложности.** После шага 8 добавьте к рецепту живого стенда заключение
   независимой проверки безопасности (q33), подписанное ключом `safety_engineer`, и снова получите
   решение гейта:

   ```bash
   ./lab.sh cli recipe safety batch-prep --result APPROVED     # или REJECTED
   ./lab.sh cli recipe approve batch-prep --no-approve --device http://device:8080
   ```

   Как меняются индекс и решение при положительном и отрицательном заключении? Какую модель объекта
   должен использовать инженер по безопасности, чтобы его заключение остановило RM1?

## Контрольные вопросы

1. Почему условия приёмки партии гейт берёт из подписанного технологического задания, а не из
   проверок, записанных в самом рецепте?
2. Агент выполнил пробный прогон, получил опустошение и всё равно загрузил рецепт. Какое свидетельство
   это фиксирует и почему его фиксирует сервер, а не агент?
3. Чем аттестация авторства отличается от утверждения оператора? Что меняется, если у нарушителя есть
   и ключ агента, и ключ оператора?
4. Почему для рецептов, как и для образов, нужен антиповтор, хотя повторно исполняемый рецепт
   подлинный и когда-то был допущен?
5. Подменённый мост MCP может подделать и ответы агенту. Какие свидетельства от этого не зависят?
6. Какие меры остановили бы RM1 и RM2 и почему они лежат вне допуска рецептов?
