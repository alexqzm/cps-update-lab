# ЛР-5. Загрузка логики с подложной инженерной станции

**Сценарий:** A6. **Продолжительность:** 2 академических часа.

## Цель

Показать, что у контроллера есть второй путь изменения ПО — загрузка логики с инженерной
станции, — который обходит загрузчик и его проверку подписи. Разобрать, почему инженер не видит
подмену на своей станции и как квитанция гейта закрывает этот путь.

## Связь с реальными атаками

- [Stuxnet (2010)](https://github.com/alexqzm/cps-supply-chain-atlas/blob/main/data/records/stuxnet-2010.yaml):
  на компьютере программирования подменялась библиотека, через которую STEP 7 обменивается
  блоками кода с ПЛК; в ПЛК внедрялись собственные блоки, которые скрывались при чтении;
- [TRITON (2017)](https://github.com/alexqzm/cps-supply-chain-atlas/blob/main/data/records/triton-2017.yaml):
  с инженерной станции системы ПАЗ в контроллеры Triconex по протоколу TriStation добавлялась
  программа нарушителя;
- [PLC-Blaster (2016)](https://github.com/alexqzm/cps-supply-chain-atlas/blob/main/data/records/plc-blaster-2016.yaml):
  червь в виде программы ПЛК копирует себя в другие ПЛК по инженерному протоколу;
- [Rogue7 (2019)](https://github.com/alexqzm/cps-supply-chain-atlas/blob/main/data/records/rogue7-2019.yaml):
  подложная инженерная станция загружает в ПЛК S7-1500 одну программу, а инженер в TIA Portal
  видит исходный код другой.

## Теория

Канал обновления доставляет образ через загрузчик: на L1 загрузчик проверяет подпись
поставщика. Инженерная станция загружает логику по сети напрямую в среду исполнения, мимо
загрузчика. Логику пользователя поставщик не подписывает, поэтому подпись загрузчика к ней не
применима, и на стенде на L0 и L1 загрузка логики ничем не проверяется. Подложная станция в
сценарии показывает инженеру подлинную программу 1.1.0, а в контроллер загружает вредоносную.

На L2 контроллер требует квитанцию гейта на обоих путях: и для обновления, и для загрузки логики.
Без квитанции изменение не принимается. Подлинную программу инженер загружает вместе с
квитанцией, которую гейт выдал на этот выпуск.

## Подготовка

```bash
./lab.sh up
```

## Ход работы

1. **L1: подмена на инженерной станции.** Выполните `./lab.sh scenario A6 1`. В выводе сценария
   найдите программу, которую видит инженер. Сравните её с программой, которая работает в
   контроллере (HMI: уставки и блокировки; `./lab.sh status`).

2. **Как обнаружить.** Сравните SHA-256 образа в `./lab.sh status` с SHA-256 выпуска 1.1.0 из
   `./lab.sh cli release list`. Выполните `./lab.sh monitor`.

3. **L2: загрузка без квитанции.** Выполните `./lab.sh scenario A6 2`. Запишите код отказа.

4. **L2: загрузка с квитанцией.** Загрузите в контроллер подлинную программу с квитанцией и без
   неё:

   ```bash
   ./lab.sh cli ews download tank-1.1.0
   ./lab.sh cli ews download tank-1.1.0 --receipt tank-1.1.0
   ./lab.sh cli ews download tank-1.0.0 --receipt tank-1.0.0
   ```

   Запишите исход каждой загрузки и объясните третий.

5. **Отчёты контроллера.** Откройте журнал в HMI или выполните `./lab.sh monitor`. Какие записи
   появились на шагах 3–4 и что в них указано в поле «путь»?

## Ожидаемые результаты

| Уровень | Исход | Процесс | Монитор |
|---|---|---|---|
| L0 | принято | перелив | тревога: образ не допущен гейтом |
| L1 | принято | перелив | тревога: образ не допущен гейтом |
| L2 | отказ `NO_RECEIPT` | норма | предупреждение: устройство отвергло образ |

На шаге 4: без квитанции — `NO_RECEIPT`; с квитанцией 1.1.0 — принято (scii-agent допускает
повторную установку той же версии); 1.0.0 с её квитанцией — `ROLLBACK`.

## Контрольные вопросы

1. Почему подпись поставщика, которую проверяет загрузчик, не защищает от подложной инженерной
   станции?
2. Инженер видит на станции подлинную программу. По каким данным можно доказать, что в
   контроллере другая?
3. Какие изменения в процессе эксплуатации потребует режим L2, если каждую загрузку логики нужно
   сопровождать квитанцией гейта?
4. В Rogue7 проверка целостности по HMAC проходила, потому что её вычислял сам нарушитель. Чем
   квитанция SCII отличается от такой проверки?
5. Какие ещё меры защищают путь загрузки логики (доступ к инженерной станции, пароли проекта,
   режимы ключа ПЛК)? Какие из них останавливают PLC-Blaster?
