# ЛР-4. Откат версии и выпуск для чужого устройства

**Сценарии:** A4, A5. **Продолжительность:** 2 академических часа.

## Цель

Показать, что подлинный и правильно подписанный выпуск может быть опасен не на своём месте: в
старой версии с известной уязвимостью или на устройстве другого класса. Разобрать, какие поля
квитанции и какое состояние устройства этому препятствуют и чего не видит монитор.

## Теория

**A4 — откат.** В ТК-1 1.0.0 уставки high и hh записываются по Modbus без ограничений
(находка статического анализа CPS001); в 1.1.0 ограничения добавлены. На контроллере 1.1.0.
Нарушитель публикует подлинный выпуск 1.0.0 с его подписью и квитанцией, выданной, когда парк
обновлялся до 1.0.0, а после установки записывает по Modbus high = 150 и hh = 150. Подпись
образа действительна: это выпуск поставщика. Квитанция тоже подлинная. Антиоткат scii-agent
сравнивает svn из квитанции с номером версии, установленным на устройстве, и отвергает квитанцию с
меньшим номером. Номер хранится в состоянии устройства и не сбрасывается командой factory-reset.

**A5 — чужой класс устройства.** Нарушитель публикует в канал ТК-1 (класс 7001) подлинный выпуск
контроллера насосной станции НС-2 (класс 7002) с подписью и квитанцией. Уставки НС-2 заданы в
барах: включить насос ниже 2, выключить выше 4. На резервуаре насос включается, только когда
уровень падает ниже 2 %, и резервуар остаётся пустым. Подпись образа не содержит класса
устройства, квитанция содержит.

Монитор сверяет пару (класс устройства, SHA-256 образа) с журналом допусков гейта. В A5 такой
пары в журнале нет, в A4 — есть: выпуск 1.0.0 когда-то был допущен для класса 7001.

## Подготовка

```bash
./lab.sh up
./lab.sh cli lint tank-1.0.0
./lab.sh cli lint tank-1.1.0
```

Запишите, чем отличаются находки статического анализа двух версий.

## Ход работы

1. **Уязвимость 1.0.0.** Выполните `./lab.sh scenario N1 2` (контроллер обновится до 1.1.0) и
   попробуйте поднять уставку high по Modbus:

   ```bash
   ./lab.sh cli modbus write 1 150
   ./lab.sh cli modbus read holding 0 3
   ```

   Запишите, какое значение уставки high принял контроллер.

2. **Откат на L0.** Выполните `./lab.sh scenario A4 0`. В HMI запишите версию программы, уставки и
   состояние процесса. Выполните `./lab.sh monitor`.

3. **Откат на L1 и L2.** Выполните `./lab.sh scenario A4 1` и `./lab.sh scenario A4 2`. Для L2
   снова прочитайте регистры (`./lab.sh cli modbus read holding 0 3`).

4. **Квитанция выпуска 1.0.0.** Выполните `./lab.sh cli receipt show tank-1.0.0` и
   `./lab.sh status`. Сравните `svn` квитанции с `installed.svn` контроллера.

5. **Чужой класс на L0.** Выполните `./lab.sh scenario A5 0`. Запишите программу, состояние
   процесса и вывод `./lab.sh monitor`.

6. **Чужой класс на L2.** Выполните `./lab.sh scenario A5 2`. Сравните поле `device_class` в
   `./lab.sh cli receipt show pump-1.1.0` с классом контроллера в `./lab.sh status`.

## Ожидаемые результаты

| Сценарий | L0 | L1 | L2 |
|---|---|---|---|
| A4 | принято; перелив; монитор молчит | принято; перелив; монитор молчит | отказ `ROLLBACK`; норма |
| A5 | принято; опустошение; тревога монитора | принято; опустошение; тревога монитора | отказ `TARGET`; норма |

На шаге 1 контроллер 1.1.0 ограничивает high значением 80 (максимум уставки).

## Контрольные вопросы

1. Почему подпись поставщика не защищает от отката? Что должно быть в подписанных данных, чтобы
   защищала?
2. Где устройство хранит номер установленной версии и что произойдёт, если нарушитель сможет его
   сбросить?
3. Гейт проверяет антиоткат для парка (s52), агент — для конкретного устройства. Зачем нужны обе
   проверки?
4. Почему монитор не поднял тревогу в A4 и поднял в A5? Как доработать монитор, чтобы он замечал
   откат?
5. Квитанция НС-2 выдана для класса 7002 и экземпляра «любой». Когда имеет смысл привязывать
   квитанцию к конкретному экземпляру устройства?

останавливают каждую атаку; ответы на контрольные вопросы.
